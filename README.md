# Belarus RP Launcher

Лаунчер для проекта «Беларусь RP» (GTA V, RAGE MP). Windows 10/11, x64, WPF на .NET 8.
Собирается в один файл `BelarusRP.exe`, .NET устанавливать игрокам не нужно.

> .NET 8, а не .NET Framework 4.8: он современнее, собирается в один самодостаточный exe
> и работает на Windows 10/11.

## Что умеет

| Функция | Как работает |
|---|---|
| Поиск GTA V | Реестр + стандартные папки Steam/Rockstar/Epic на всех дисках, проверка `GTA5.exe`. **Проверяет наличие игры, но не доказывает, что копия лицензионная.** |
| Поиск RAGE MP | Реестр, `C:\RAGEMP`, либо выбор файла вручную |
| Серверы и статус | Список из конфига, статус по TCP-подключению (онлайн/оффлайн) и время соединения |
| Вход и регистрация | Через **ваш** API по HTTPS, токен шифруется Windows DPAPI |
| Запуск | `rage://v/connect?ip=хост:порт`, запасной вариант: запуск `ragemp_v.exe` с тем же адресом |
| Целостность файлов | Сверка SHA-256 клиента RAGE MP с манифестом (опционально) |
| Автообновление | GitHub Releases, проверка SHA-256, замена exe и перезапуск |
| Интерфейс | Русский/английский, анимация запуска, окно меняет размер, цвета: красный, белый, синий |
| Журнал и отчёты | `%AppData%\BelarusRP\launcher.log`, кнопка «Отчёт об ошибке» |
| Статистика | Только локальная: счётчики запусков в `%AppData%\BelarusRP\stats.json`, никуда не отправляется |

## Честно о том, чего здесь нет

- **Античита нет.** Лаунчер проверяет файлы по манифесту и ищет запущенные программы из
  чёрного списка (`blockedProcesses`), но обойти это легко. Реальная защита от читов
  делается на стороне сервера (серверные проверки, логи, баны).
- **Сервера аккаунтов нет.** Для входа и регистрации нужен ваш бэкенд с двумя методами
  (описание ниже). Пока `apiBaseUrl` пустой, кнопки сообщат, что сервер не настроен.
  По умолчанию вход не обязателен (`requireLogin: false`), играть можно без него.
- **Ник игрока в RAGE MP лаунчер не задаёт.** Имя берётся из настроек клиента RAGE MP.
- **Обновление игры GTA V лаунчер не проверяет:** это делают Steam, Rockstar или Epic.
- **exe не подписан.** При первом запуске Windows SmartScreen может показать предупреждение.
  Убрать его можно только подписью сертификатом (code signing).

## Настройка перед сборкой

Откройте `config/launcher.config.json`:

- `githubOwner` и `githubRepo`: ваш аккаунт и репозиторий на GitHub. **Без них автообновление выключено.**
- `servers`: имя, адрес и порт сервера. `statusPort`: порт для проверки статуса (0 = тот же, что `port`).
  Если сервер не отвечает на TCP по игровому порту, укажите порт, который отвечает.
- `siteUrl`, `newsUrl`, `vkUrl`, `discordUrl`: ссылки (только `https://`).
- `apiBaseUrl`: адрес вашего API аккаунтов, например `https://api.belarus-rp.ru`.
- `requireLogin`: `true`, если без входа играть нельзя.
- `reportUrl`: куда отправлять отчёты об ошибках (необязательно).
- `filesManifestUrl`: адрес манифеста для проверки файлов (необязательно).
- `blockedProcesses`: имена процессов без `.exe`, которые нужно закрыть перед игрой.

Файл `launcher.config.json` рядом с exe (если положить) имеет приоритет над вшитым.

### API аккаунтов (если нужен вход)

```
POST {apiBaseUrl}/auth/login     {"login":"...","password":"..."}  ->  {"token":"..."}  или  {"error":"текст"}
POST {apiBaseUrl}/auth/register  {"login":"...","password":"..."}  ->  {"ok":true}      или  {"error":"текст"}
```

### Манифест файлов (если нужна проверка)

```json
{ "files": { "ragemp_v.exe": "sha256-в-hex", "client_packages/index.js": "sha256-в-hex" } }
```

Пути относительные от папки клиента RAGE MP (где лежит `ragemp_v.exe`).

## Как собрать и выложить на GitHub

1. Создайте на GitHub **публичный** репозиторий, например `BelarusRP-Launcher`.
   (Из приватного нельзя скачивать обновления без токена.)
2. Заполните `config/launcher.config.json`.
3. В папке проекта выполните:
   ```
   git init
   git add .
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/ВАШ_АККАУНТ/BelarusRP-Launcher.git
   git push -u origin main
   ```
4. Выпустите первую версию:
   ```
   git tag v1.0.0
   git push origin v1.0.0
   ```
5. Вкладка **Actions**: через 3-5 минут сборка завершится, и в **Releases** появятся
   `BelarusRP.exe` и `BelarusRP.exe.sha256`.
6. Ссылка для скачивания на сайте (всегда последняя версия):
   `https://github.com/ВАШ_АККАУНТ/BelarusRP-Launcher/releases/latest/download/BelarusRP.exe`

Если Actions не может создать релиз, откройте *Settings -> Actions -> General -> Workflow
permissions* и включите **Read and write permissions**.

## Как работает автообновление

1. При запуске и раз в 6 часов лаунчер запрашивает `releases/latest` вашего репозитория.
2. Если `tag_name` (например `v1.0.1`) новее текущей версии, появляется синий баннер.
3. По кнопке «Обновить» скачивается `BelarusRP.exe`, считается SHA-256 и сверяется с
   `BelarusRP.exe.sha256` из того же релиза. Нет файла суммы или она не совпала: обновление отменяется.
4. Лаунчер закрывается, маленький скрипт подменяет exe и запускает новую версию.

Чтобы выпустить обновление: измените код, добавьте запись в `CHANGELOG.md`,
выполните `git tag v1.0.1` и `git push origin v1.0.1`.

Ограничение: проверка суммы защищает от повреждённой загрузки, но не от взлома вашего
репозитория. Для защиты от этого нужна цифровая подпись exe.

## Локальная сборка

Нужен [.NET 8 SDK](https://dotnet.microsoft.com/download/dotnet/8.0). Запустите `build.bat`,
результат: `publish\BelarusRP.exe`. Размер файла около 70-100 МБ, потому что внутри .NET.

## Данные на компьютере игрока

`%AppData%\BelarusRP\`: `settings.json` (токен хранится зашифрованным), `launcher.log`, `stats.json`.

## Лицензия

Лицензионные условия не включены в этот релиз. Не используйте и не распространяйте лаунчер
без отдельного разрешения правообладателя.

## Тесты
```
dotnet test tests/BelarusRP.Tests/BelarusRP.Tests.csproj -c Release
```
На GitHub они запускаются автоматически (`.github/workflows/ci.yml`). Только Windows (WPF + DPAPI).

## Что в проекте НЕ реализовано (нужен ваш бэкенд или сторонний сервис)
- Облако и аккаунты: лаунчер ждёт API по `apiBaseUrl`, самого сервера нет.
- Настоящий античит: есть только проверка списка процессов и файлов; защита должна быть на сервере.
- Платежи и push-уведомления: не реализованы (платежи нельзя делать без платёжного провайдера и юридического оформления).
- Новости читаются со страницы по ссылке, а не из ленты.
